# dsh-spirit 定位书（v0.10）

> 一句话：**spirit 不是记忆库，是这条鱼的生平。**

---

## 0. 为什么要重定位

v0.9 之前，spirit 的自述是「第一人称体验与本体记忆插件」，对外露出的主界面叫「记忆星海」「翻阅」。
但真机上跑下来，这两个面呈现的东西和"记忆"这个词承诺的东西不是一回事。三条硬证据（本机库实测）：

1. **条目库只剩摩擦。** 全库 22 条体验条目，触发分布是
   `tool_failure 14 / recovery 4 / task_close 3 / user_interruption 1`，
   `neutral` 因为人格卡写着「平常一轮: 0」永远不落库。
   而真实的工作日里绝大多数轮次是"顺利干活"，于是**干了什么从来不进库**。
2. **进库的句子不带内容。** 22 条里 73 行跨会话同句——文案是
   「手边的动作没成，我记着这一下」这种固定模板 + 人格语气。
   作为"记忆"，它的信息量是零：既不能回答"上周做了什么"，也不能回答"那个坑最后怎么解决的"。
3. **"事"是靠邻居借来的。** 星海上的 139 个"交付物"点全部来自
   `prime-memory` 的 L1 重建（`l1-dlv:` 前缀），spirit 自己的本体抽取轨一条也没产出。
   也就是说：**spirit 展示的记忆主体，内容不归它所有。**

所以问题的根不是"记忆没做好"，而是**把一层情绪原料包装成了记忆产品**。
越往里加召回、加记忆工具，就越和 `dsh-fish-memory`/`agent-soul`/`prime-memory` 撞车，
而且撞不赢——它们的记忆有内容，这个没有。

---

## 1. 新定位

**spirit = 经历层（episodic self）。**

它回答的问题不是「这条事实能召回吗」，而是：

> **我是怎么走到今天这一步的？**

因此它只持有一条时间轴，轴上有四样东西：

| 轴上的东西 | 来源（全部已有，不新造采集） | 它回答 |
|---|---|---|
| **事**（delivery） | 事务轨 `txn_entry` / 本体交付（`dlv-`、`l1-dlv:`） | 我做成过什么 |
| **感**（feel） | 体验条目（机械分类，零模型） | 那一下我是什么反应 |
| **线**（milestone） | 生涯流程档 `distill_digest` 的 session/week/month/milestone 档 | 那段日子整体是什么样 |
| **缘**（bond） | 回声链 `causal_edge` + 主题 `topic` + 主人档案 `owner` | 这些事之间、和这个人之间，是怎么连起来的 |

**产品形态随之改变：主界面从「记忆星海 / 条目库」变成「编年」。**
星海仍然是这张轴的拓扑视图（谁因谁果、哪段最亮），但它不再自称记忆库。

## 2. 与四个邻居的边界（必须能一句话说清）

| 插件 | 它负责的 | 它的核心问题 | spirit 与它的区别 |
|---|---|---|---|
| **dsh-soul** | 说话方式 / 人设配置 | 模型该用什么口气说话 | spirit 不配人格。人格卡是它的**输入**（决定在意什么），不是它的产品 |
| **dsh-fish-memory** | 会话级事实条目（会淡忘） | 这条事她记不记得 | spirit 不记事实。事实一条都不抢，也不做召回 |
| **dsh-agent-soul** | 人格 + 记忆卡 + 心情状态机 + 日记 | 她此刻是谁、什么心情 | spirit 不做状态机、不写日记、不判心情。它记录的是**已经发生过的**经历，不是当前状态 |
| **dsh-prime-memory** | 知识事实 L1→L3 蒸馏 | 模型该知道什么 | spirit 不蒸馏事实、不做向量召回。它只读 L1 的交付结果当"事"的素材（可选，缺席不影响） |
| **dsh-spirit** | **经历编年：事 + 感 + 线 + 缘** | **我这一路是怎么过来的** | 唯一做"时间轴 + 因果 + 可视化回顾"的那一个 |

### 反面纪律（写进代码注释与门禁，防止回滑）

- ❌ **不做事实召回。** 不新增"按 query 找回忆"的注入面；召回是邻居的活。
  现有 `spirit-search` 只服务面板检索，不进注入。
- ❌ **不做人格配置。** 不提供改语气/改自称以外的风格设置；那是 soul 的活。
  （`spirit_selfname` 保留，因为自称属于"我"，不属于"配置"。）
- ❌ **不做实时心情。** 不引入每轮模型判定、不做心情时间线。情绪只有"这一条经历的强度"，
  没有"当前状态"（当前状态是 agent-soul 的活）。
- ❌ **不写日记。** 不做按天八股的日记生成。编年是**事件驱动**的，不是打卡驱动的。
- ✅ **只做加法。** 所有新能力都不许要求用户改配置才能看到效果（编年默认开）。

## 3. 三张面各自的读者

| 面 | 读者 | 形状 | 纪律 |
|---|---|---|---|
| **编年**（新，默认） | 人 | 按天分段，事在前、感在后 | 事是主体（有标题有结果）；感是注脚，可折叠；同日同句才敢报 `×N` |
| **星海** | 人 | 拓扑，亮度=新鲜度，连线=因果 | 交付点与体验点同一张图，不把"事"画成配角 |
| **回忆卡**（注入） | 模型 | 尾部 ≤640B | 只讲"此刻 + 刚发生 + 想到什么 + 一条暖的"，不试图当事实源 |

**验收标准**（怎么算定位改对了）：

1. 打开默认面，第一屏能看到"我这周做成的事"，而不是"我又出错了"。
2. 连续三相同时装（spirit + fish-memory + agent-soul），注入里不出现两套"记忆"话术打架。
3. 关掉 `prime-memory` 后，编年仍有内容（事可以由自己的本体轨供给，缺了只是变稀）。
4. 把体验条目全藏起来，编年仍然读得通——**事不依赖感**。

## 3.5 「温度」这一层（v0.11）：从上游借判断，不借存储

编年的四条轴都是"已经发生的事"，但事与事的分量不同：有的坑三个月后还记得，有的第二天就凉了。
这一层就是给轴上的条目定**冷暖**。

### 借的是 fish-memory 的判断，不是它的仓库

| fish-memory 的机制 | spirit 的等价物 | 差别 |
|---|---|---|
| 重要度决定降得多慢 | `importanceOf` → `halfLifeOf` | 直接吃上游 `priority` / `persistence`，不重算 |
| 连续半衰的鲜活度 | `freshnessOf = 0.5^(Δt/halfLife)` | 与自家 `recall/form.ts` 淡出**同式** |
| 被想起会强化 | `recallHeatOf` ← 自家 `echo_ref.times` | 用**自己的**引用账，不用上游召回账 |
| 会淡忘但不删 | `valid_to` → 折减 0.55 | 与自家 append-only 一致 |

不借的三样：**会话级事实条目**、**`remember` 工具**、**按 query 召回**。
那三样正是与 fish-memory 撞车的部分，也是 v0.9 的病根。

### 为什么从 prime-memory 取料

上游蒸馏时已经为每条 L1 算过 `priority`、标过 `persistence`、写过 `valid_to`——判断**花过钱**了。
spirit 重算一遍只会得到更好看的第二真源，而两者分歧无从裁决。
所以：**事实归 prime，经历归 spirit**。spirit 只持有"我什么时候知道这件事、它在我这儿多暖"。

### 分类基准（实测逼出来的，不许改回单基准）

| 类别 | 半衰基准 | 理由 |
|---|---|---|
| `learned`（关于世界） | 3 天 | 流水事实本就该凉得快 |
| `bond`（关于这个人） | 21 天 | 关系记忆该记得久；用同基准会把偏好记成"快忘了" |

单基准（30 天，与编年窗口同宽）下真机分布是 `hot 756 / warm 226 / cool 0 / faded 0`——
四档里两档永不出现，温度只是装饰。改分类基准后 `321/167/360/134`，四档齐全。

### 注入面的三道闸（这一层唯一"往外送"的地方）

面板宽松无所谓，**注入面每轮都在花 token 和注意力**，而且会与 fish-memory / agent-soul 的注入段重叠：

1. **type 白名单**：只认 `user_info/user_hobby/user_communication/user_behavior`。
   实测 chat 家族 58 条里 `instruction 15` 是**用户指令**——当回忆重放等于陈旧指令复现；
   `persona 8` 属 soul 系列；`episodic 11` 多数已失效。
2. **安全闸**：`hitsInjection` + `containsSecret`。
3. **重复闸**：冷却 24h + 近义去重 Jaccard ≥0.7（实测 19 条干净候选里有 3 条是同一偏好的三个版本）。

**沉默优先于重提**：近义候选里旧版本更容易过闸（更长、token 更多），无条件放松等于让旧说法盖掉新说法。
只在连续 7 天没注入过时才放松。

## 4. 落地路线

- **v0.10（本次）**：编年面（`chronicle-list` + 翻阅默认视图）+ 交付/里程碑/记着入轴 + 同日同句聚合。
- **v0.11（已发）**：温度层 + 注入面「暖：」段（见 §3.5）。
- **v0.12**：因果连线进编年（点开一条事能看到"因为哪次失败才改的"），`causal_edge` 已有表。
- **v0.12**：关系线（owner 档案 + bond 记忆合成"我们走到哪了"的一段）。
- **不做**：事实召回、心情状态机、日记生成、向量检索。
